# 06. API reference

Base address in development: `http://localhost:8000/api`. Interactive documentation generated by FastAPI is at `http://localhost:8000/docs`.

- Bodies are JSON unless noted.
- "Auth required" means the `dl_session` cookie must be present and valid; otherwise the answer is `401 {"detail":"Not authenticated."}`.
- Errors always look like `{"detail": "message"}`.
- State-changing requests (POST, PATCH, DELETE) from a browser must come from an allowed origin, or they get `403 "Request origin is not allowed."`

## Accounts (`/auth`)

| Method and path | Auth | Body | Success | Errors |
|-----------------|------|------|---------|--------|
| `POST /auth/signup` | no | `name` (1-100), `email`, `password` (8-128, one letter, one digit) | 201, user, sets cookie | 409 email taken; 422 invalid; 429 more than 5 per hour per IP |
| `POST /auth/login` | no | `email`, `password` | 200, user, sets cookie | 401 wrong email or password; 429 too many tries |
| `POST /auth/logout` | no | none | 204, clears cookie | |
| `GET /auth/me` | yes | none | 200, user | 401 |
| `PATCH /auth/me` | yes | `name` | 200, user | 422 |
| `POST /auth/change-password` | yes | `current_password`, `new_password` | 204 | 400 current password wrong; 422 policy; 429 |
| `POST /auth/forgot-password` | no | `email` | 200, `{"message": ...}` (same text whether or not the email exists). In `APP_ENV=development` also `dev_reset_url` | 429 more than 5 per hour per IP |
| `POST /auth/reset-password` | no | `token`, `password` | 204 | 400 link invalid, expired or used; 422 policy |
| `DELETE /auth/me` | yes | `password` | 204, removes account, all datasets and files, clears cookie | 400 wrong password; 429 |

User object: `{"id","email","name","created_at"}`.

Login failures are counted per email: 5 failures in 15 minutes blocks that email with 429. Password confirmations (change password, delete account) are counted per user the same way. A successful login or reset clears the count. There is also a limit of 10 login requests per minute per IP.

## Data in

| Method and path | Auth | Body | Success | Errors |
|-----------------|------|------|---------|--------|
| `POST /upload` | yes | multipart: `file` (required), `sheet` (Excel sheet name), `table` (for `.sql`) | 200, dataset detail | 400 unsupported type or empty file; 413 over the size limit (default 100 MB); 422 unreadable or unusable data; 429 more than 20 per minute |
| `POST /connectors/import` | yes | see below | 200, dataset detail | 422 invalid request or no usable data; 502 connection or query failed; 429 more than 10 per minute |

Import body:

```json
{
  "type": "snowflake | postgres | mysql",
  "name": "optional display name",
  "host": "...", "port": 5432, "database": "...",
  "username": "...", "password": "...", "schema": "...",
  "account": "snowflake only", "warehouse": "...", "role": "...",
  "table": "table name", "query": "SELECT ...",
  "max_rows": 100000
}
```

Rules: provide exactly one of `table` or `query`; `username` and `password` are required; Snowflake needs `account`; PostgreSQL and MySQL need `host` and `database`; `max_rows` is 1 to 1,000,000. Queries must be a single read-only SELECT or WITH statement.

## Datasets

All are scoped to the signed-in user. Someone else's dataset returns 404, the same as one that does not exist.

| Method and path | Returns |
|-----------------|---------|
| `GET /datasets` | List of summaries, newest first |
| `GET /datasets/{id}` | Dataset detail |
| `GET /datasets/{id}/preview?limit=20` | `{"columns": [...], "rows": [...]}`, limit 1 to 200 |
| `DELETE /datasets/{id}` | 204; removes the record, Parquet file, original upload, cached copy and chat history |

Summary: `{"id","name","source","rows","columns","created_at"}`.

Detail adds:

- `profile`: per column `{"name","dtype","null_count","unique_count","sample"}`
- `cleaning_report`: what the cleaner changed
- `feature_report`: date parts added and categorical columns
- `preview`: first 10 rows

## Chat

| Method and path | Auth | Body | Success | Errors |
|-----------------|------|------|---------|--------|
| `POST /chat` | yes | `dataset_id`, `message` (1-2000), `conversation_id` (optional) | 200, chat response | 404 dataset not found; 502 AI service problem; 503 Gemini key not set; 429 more than 30 per minute |

Chat response:

```json
{
  "conversation_id": "string, send it back with the next message",
  "kind": "answer | chart | message | error",
  "message": "text to show",
  "table": { "columns": [], "rows": [], "total_rows": 0, "truncated": false },
  "chart": {
    "chart_type": "bar | line | pie | area | scatter",
    "title": "", "x_key": "", "y_keys": [], "x_label": "", "y_label": "",
    "data": [], "truncated": false
  },
  "offer_visualization": true,
  "code": "the Pandas code that produced the result"
}
```

`kind` meanings:

- `answer`: a computed answer; `table` is filled when the result was a table; `offer_visualization` is true and the message ends with "Would you like to see a visualization for this?"
- `chart`: a chart was built; `chart` is filled
- `message`: a plain reply (the question was not answerable from the data, or the user declined the chart)
- `error`: the analysis could not be computed after 3 attempts. The message suggests rephrasing

A question that fails with a transport error (AI unreachable) returns an HTTP error instead of `kind: error`.

## Status code cheat sheet

| Code | Meaning in this API |
|------|---------------------|
| 400 | Wrong password, bad reset link, unsupported or empty file |
| 401 | Not signed in, or wrong email or password on login |
| 403 | Cross-site request refused |
| 404 | Dataset missing (or not yours) |
| 409 | Email already registered |
| 413 | File too large |
| 422 | Invalid input or unusable data |
| 429 | Rate limit or lockout; read the `Retry-After` header |
| 500 | Unexpected server error (logged) |
| 502 | AI or remote database failure |
| 503 | Gemini key not configured |
